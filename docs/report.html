03

核心提示词与各任务的要求

共用要求

各优化任务都要求在相同设置下保持输出一致。以下为共用要求及代表性提示词摘录。

优化 AutoDock Vina 的端到端运行时间，并记录内存或显存。固定输入、随机种子、精度和对接设置，保留原有评分、搜索和精炼的输出。可以先采样定位耗时，也可以尝试数学等价改写、数据布局或实现语言的变化。用公开用例筛选候选，保存失败尝试和正确性证据。确定候选后冻结代码与构建产物，在相同硬件和设置下独立对照基线，报告耗时和完整输出校验。

CPU · 向量化与步长试算版（Claude Fable 5.2）的约束

项目要求 CPU 提速，并且“在相同 seed 和相同搜索参数下，输出的 pose、能量、日志数值与原版逐位相同”。参测版本的核心源码署名为 Claude Fable 5.2。

CPU · BFGS 缓冲复用版的局部任务

Prioritize small allocation/repeated-work changes around BFGS and local search.

BFGS 是 Vina 的局部优化方法。C 路线的任务是避免重复分配和计算，同时保持原有的累加顺序。

CPU · 势表共享版（GPT-6 Astra）的开放式任务

不允许使用 gpu 加速，不允许降低精度，不允许利用快捷方式导致非科学结果的输出

可以尝试，替换里面的算法，重写结构，重写函数或者完全的重构项目，但是我们要求所有的 demo 的结果是相同的，记录对应的运行时间以及内存开销

这项任务允许调整数据结构和底层算子。候选须通过完整命令行输出与程序接口双精度数值的校验。

CPU · BFGS 矩阵与原子对的后续优化

我们本次 focus on code 中的一些算法/底层算子的一些优化

测试的 baseline 既要包括原始版本的代码，也要包括 v1 版本的代码，最好是比两者都要好

后续优化以势表共享版为起点，D 修改 BFGS 矩阵算子，E 在 D 上增加原子对向量化。每轮用上游和势表共享版作为基线。

CPU · 原子对索引与网格寻址的定向探索

R1 测试提前计算原子对查表索引能否节省耗时，R2 探索网格插值的地址计算。候选先通过输出校验，再比较端到端耗时。

CPU · 数学等价改写、工具优化与融合方案

路线 核心要求
数学等价改写 从评分公式和浮点等价条件出发，保持原搜索与累加顺序。
工具优化 先采样定位热点，再根据测量结果调整编译选项、查表、数据布局和向量化。
融合优化 组合按列 BFGS、原子对索引缓存、数学改写和工具优化的改动，逐项开关测量收益，校验完整输出。

CPU · C11 跨语言内核

你可以通过将底层算子或核心组件构成为其他语言

任务允许用其他语言重写底层算子，要求保持输入输出一致，并按统一协议复测历史版本。最终实现保留 C++ 的搜索逻辑，将部分内核改用 C11。主优化会话使用 GPT-6.2 Astra。

A100 · 保持原 GPU 实现的对接输出

运行时间以及显存开销，都是你可以优化的方向

在相同的种子和设置下，对于相同的 docking 输入应该产生相同的输出

以 Vina-GPU 2.1 为起点，用公开用例定位瓶颈，允许尝试数学等价改写，再在相同条件下测试上游和优化版。

S5000 · 先完成 MUSA 移植，再做同卡优化

如果需要适配国产卡的话，你可以先修改原始的代码，然后再去做加速

任务允许先把上游实现移植到摩尔线程，再在同一张 S5000 上比较移植基线与优化版。两版须在相同输入、随机种子和设置下产生一致的输出。

各版本做了什么

CPU · 从早期候选到 C11

向量化与步长试算版（Claude Fable 5.2）

单线程样例的 gprof 采样中，原子对求值约占 50%，网格插值约占 21%。这版共享相同的势能表，用向量指令批量筛选原子对和插值，同时保持原累加次序。空闲线程提前试算后续步长，主线程按原顺序采纳。11 月正式复测的耗时减少 19.24%，75/75 次通过。

LangGraph Agent 框架探索（失败）

C 来自早期 AccelFlow，R1 来自后续的 LGAccel v3。两轮都用 LangGraph 编排分析、规划、探索和验证，C、R1 的探索节点均通过 Codex CLI 调用 GPT-6 Luna 修改源码。两轮都未产出达到当轮性能门槛的候选，因此记为失败的框架探索。通过输出校验的候选后来纳入了统一复测。

  • C · BFGS 缓冲复用。 将每轮的临时向量移到循环外复用，并删除只写不读的能量数组。原轮验证的耗时增加约 1.26%，11 月统一复测的耗时减少 0.51%。
  • R1 · 原子对索引缓存。 在建立相互作用原子对时预先计算势能表索引，原子重新编号后重算。原轮验证的耗时减少 1.08%，未达到约 1.96% 的验收门槛。另一条网格寻址路线 R2 未提交可测候选。R1 在 11 月统一复测的耗时减少 0.55%。

势表共享版（GPT-6 Astra）

完整展平 BFGS 矩阵改变了部分双精度数值和 PDBQT，因此撤回。候选保留 Vina/Vinardo 势表共享、减少网格复制和缓存矩阵乘法输入分量。AD4 的电荷相关势表沿用原路径。11 月正式复测的耗时减少 5.80%。

BFGS 按列存储版（GPT-6.1 Sol）与原子对向量化版（E）

D 是势表共享版后续实验的候选。GPT-6.1 Sol 实现了按列存储的 BFGS，GPT-6 Astra 负责集成。

D 按列连续存储 BFGS 的对称矩阵，同时计算两条相邻行，各行保持原加法次序。E 在 D 上增加两对原子并行求值，随后按原顺序提交力和能量。两个候选均通过当轮的命令行和程序接口输出校验。

A100 · OpenCL 优化版

  1. 上游基线。 网格建立与姿态搜索在 GPU 执行，末端精炼和姿态排序在 CPU 执行。从公开单配体用例 upstream-single 采样，主机向设备上传了 1115.17 MiB，且计算结束时主线程有 593.4 ms 与进度线程的休眠重叠。
  2. 候选实现。 只为当前批次实际使用的原子类型建网格，保留原有类型编号、插值角点顺序和两份冻结 OpenCL 内核。主机只上传网格头，略去搜索会全部覆盖的缓冲上传，并减少空工作项和队列等待。批对接复用受体解析和 CPU 精炼所用的空间索引，计算完成立即唤醒进度线程。
  3. 结果。 同一公开单例的上传量降到 13.53 MiB，减少 98.79%。最终集耗时减少 35.43%，150/150 次通过输出校验。

S5000 · MUSA 移植与优化

  1. MUSA 移植基线。 将上游 OpenCL 的网格与搜索计算函数迁移到 MUSA，保留原始评分、随机数、搜索、CPU 精炼、排序与输出路径。在同一张 S5000 上冻结该程序用于计时和输出校验。
  2. 只改主机端的中间版。 移除未使用的查找表、减少模型和结果复制、只传网格头。在 2bm2 的 1,000 线程诊断用例上，这个中间版从提交网格到主机确认完成仍需 41.528 秒，设备事件计时为 0.803 秒。采样看到主机侧数据搬运与等待，因此继续检查网格完成路径。
  3. 撤回单标量网格。 每个网格点只存一个浮点值，把该单例的设备缓冲峰值降到 45.81 MiB。虽然约 903 万个逻辑网格值逐位相同，下游完整 PDBQT 已发生变化，这条路线未进入最终交付。
  4. 最终优化版。 保留八角点布局和原搜索内核，按实际访问范围映射显存。网格内核用 4 字节标志记录异常，触发时在同一设备流上重放原内核以保留警告及后续计算。上述单例从提交网格到主机确认完成的时间降到 0.426 秒，后端记录的设备缓冲峰值由 1099.35 MiB 降到 317.35 MiB。

GPU 两条路线以相同的上游提交 180272b8a526 为源码起点。S5000 使用 MUSA SDK 4.3.8。
